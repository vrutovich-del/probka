## Правила работы

- Работаем по одному нумерованному пункту. Перед началом — две-три строки: что делаешь и какие файлы трогаешь. После: `npm run build` (typecheck + сборка) должен пройти, потом ровно один коммит с названием пункта. Не сваливай пункты в один коммит.
- Стоп в конце захода, ждём ревью.
- Если прототип и бриф расходятся — бриф главнее. Если прототип неоднозначен — спрашивай, не угадывай.
- Копирайт не выдумывать. Недостающие строки идут в `scripts/strings-to-json.mjs` (`APP_KEYS`) с английским текстом и перечисляются в отчёте по пункту. Хардкод текста в компонентах запрещён, всё через ключи.
- Никаких выдуманных данных. Пустые состояния настоящие. Но заглушек и неработающих кнопок тоже не надо: показываем всё, что можно посчитать честно.
- Код, комментарии, коммиты и `DECISIONS.md` — по-английски. Разговор со мной — по-русски.
- Библиотеки. Для серверной части уже согласованы: `wrangler`, `drizzle-orm`, `drizzle-kit`, `hono`. Всё остальное — только с моего разрешения, и в клиенте тоже.

## Непреложное

1. Только мобильный: цель 390×844, обязан работать на 360×800. Десктоп — то же приложение колонкой 390px по центру на чёрном.
2. Фото крышки не изменяется никогда. Вырезание даёт только альфа-маску; RGB исходных пикселей не трогаем. Оригинал хранится рядом с вырезкой. Разрешено только уменьшение до 1024 по длинной стороне.
3. Детская безопасность: ни настоящих имён, ни чатов, ни геолокации, ни рекламы, ни аналитики кроме логов ошибок. Друзья только по коду-приглашению, поиска людей нет. Родительский барьер перед удалением аккаунта и функциями друзей.
4. Офлайн прежде всего: добавление крышки работает без сети. Сервер — это фоновая синхронизация, а не условие работы.
5. Три языка — ru, en, uk, все строки из таблицы.
6. Цвета строго из токенов. Зелёный и красный никогда не единственное отличие состояния — всегда плюс форма, иконка или подпись.

## Цель этого захода: друзья

Решения владельца продукта от 20 сентября 2026. Они главнее соответствующих строк брифа.

- **Объём.** Аккаунты, синхронизация, коды-приглашения, гараж друга только на чтение, таблица лидеров среди друзей. **Дуэль не делаем** — отдельным заходом, когда друзья заработают на живых телефонах.
- **Вход без паролей и почты.** Никаких Apple и Google, вопреки брифу. Аккаунт заводится на телефоне сам, у него есть код восстановления. Причина: дешевле, а главное — о детях не хранится ничего, кроме ника, аватара и фотографий крышек.
- **Восстановление — обязательное требование.** Мы как создатели должны уметь вернуть ребёнку гараж и перенести аккаунт на новый телефон, даже если код восстановления потерян. Без этого пункт 5 не закрыт.
- **Сервер.** Cloudflare Workers + D1 + R2 на бесплатном тарифе, вместо Hetzner + Fastify + PostgreSQL из брифа. Лимиты на сентябрь 2026: Workers 100 тыс. запросов в день, D1 5 ГБ, 5 млн прочитанных и 100 тыс. записанных строк в день, R2 10 ГБ и 1 млн операций записи в месяц. Для десятка детей запас большой. Drizzle из брифа остаётся — у него есть драйвер D1.
- **Фотографии — в R2.** Владелец привязал платёжные данные и включил R2 20 сентября, так что храним на сервере и оригиналы, и вырезки, и миниатюры: потерянный телефон восстанавливается целиком. В D1 блобы не класть.
- **Редкость — как в брифе:** ранг появляется после 20 владельцев типа. Значит, в кругу из пяти друзей все крышки останутся Unrated, и это нормально: метрика «редчайшая крышка» в таблице лидеров честно покажет, что рангов ещё нет. Дуэль ждёт того же.

## Пункты этого захода

**Пункт 1 — каркас сервера.** Каталог `server/` в этом же репозитории: Worker на Hono, Drizzle на D1, R2 для фотографий, `wrangler.toml`, миграции, эндпоинт здоровья. CORS только для `https://vrutovich-del.github.io`. Деплой — `wrangler deploy` руками, не из Pages-воркфлоу: секреты Cloudflare туда класть нельзя. Адрес воркера приходит в клиент через `VITE_API_URL`, подставляется в `.github/workflows/pages.yml`. Клиент без сервера обязан работать как раньше: если `VITE_API_URL` пуст, приложение ведёт себя как в Фазе 1.

**Пункт 2 — аккаунт, ник, согласие родителя.** Экраны 05 (ник и аватар, включая предупреждение «похоже на настоящее имя») и 06 (согласие родителя), барьер с примером 6×7 перед функциями друзей. Аккаунт на сервере: id, ник, аватар, код друга вида `K7M-4QZ` (без похожих символов 0/O/1/I), дата создания. Устройство получает долгий `device_token`, он же bearer; токенов у аккаунта может быть несколько. Код восстановления показывается один раз, с просьбой отдать его родителю. Гостевой гараж при создании аккаунта сливается, ничего не удаляется (экран 37).

**Пункт 3 — синхронизация.** Очередь в Dexie: каждое изменение уходит на сервер, когда есть сеть, и переживает перезапуск приложения. Фотографии — в R2, метаданные — в D1. Отдавать фото только через Worker с проверкой токена: объекты R2 не должны открываться по угадываемой ссылке. Строка «Синхронизация» в Настройках с состоянием, баннер офлайна (экран 34), «Экспорт коллекции» файлом. Конфликты по сайтмапу: сервер главный по каталогу, устройство главное по фотографиям и заметкам.

**Пункт 4 — друзья.** Экраны 19–23: список друзей, входящие заявки (принять / не сейчас), добавление по коду — свой код с кнопками «Копировать» и «Поделиться» плюс поле для чужого, гараж друга только на чтение (заметки и места скрыты), таблица лидеров среди друзей по трём метрикам. Родительский барьер перед первым входом в друзей. Гостевая стена 20b уже есть — теперь у её кнопки появится настоящее действие. Ввод чужого кода ограничить по частоте, чтобы коды нельзя было перебрать.

**Пункт 5 — перенос аккаунта и админка.** Экран «Перенести гараж на новый телефон»: ввёл код восстановления — получил новый токен и свой гараж. Админская часть не на Pages, чтобы секрет не уехал в публичный бандл: локальная страничка или набор команд curl, описанных в `server/README.md`. Умеет: найти аккаунт по коду друга или нику, выпустить одноразовый код переноса на 24 часа, посмотреть и удалить содержимое, слить дубликаты типов крышек. Защита — `ADMIN_TOKEN` через `wrangler secret`.

**Приёмка захода.** Два живых телефона: сын и один друг. Завести аккаунты, обменяться кодами, увидеть гараж друг друга, проверить перенос аккаунта по коду восстановления и отдельно по админскому коду.

## Открытые вопросы ко мне

- Что показывать в метрике «редчайшая крышка» в таблице лидеров, пока у всех Unrated.
- Удаление крышки: чистим ли фото в R2 сразу или держим корзину, как 7-дневная отсрочка у аккаунта.
- Нужен ли вход «Перенести гараж» на первом запуске, до того как аккаунт вообще создан.
- Редактирование крышки: бренд и продукт сейчас не исправить, а ребёнок наделает опечаток. Куда вставить?
- Крестик выхода есть только на экране камеры; на опознании, ручном вводе и состоянии его нет.
- Строка `reveal.dup` «Another one! ×2» с жёсткой двойкой — нужен ключ с `{n}`.
- Русский и украинский переводы — черновик, нужна вычитка носителем. Там же `badges.setPending`, придуманный в пункте 4.
- На трёх картинках значков вшит английский текст. Если мешает — нужны версии без надписей.
- Перед дуэлью подтвердить правило: побеждает меньший процент (реже = меньше), как в прототипе.

## Грабли и приёмы

- Windows. Git Bash подменяет значение `BASE_PATH=/probka/` на путь Windows — переменные окружения для сборки задавай через PowerShell. Heredoc в нём тоже ломается на переводах строк: файлы пиши обычными инструментами записи.
- Пуш только по HTTPS: SSH-ключ на машине принадлежит другому аккаунту (`yocoge`) и прав на репозиторий не имеет. Токен `gh` для `vrutovich-del` уже с правом `workflow`.
- Каждый пуш в `main` пересобирает и публикует сайт (`.github/workflows/pages.yml`, ~3 минуты). Модель вырезания в git не лежит: локально один раз `npm run cutout-model` (~160 МБ в `public/cutout`, в `.gitignore`).
- Cloudflare уже подключён: `wrangler login` выполнен под `v.rutovich@gmail.com`, аккаунт `98904ece681dccf28dac6394ef45088d`, токен лежит в профиле пользователя. Прав хватает на Workers, D1, Pages и R2. Отдельного скоупа `r2` у `wrangler login` нет и не нужно: если R2 не включён в панели, запросы к нему падают с `code: 10042` — это не про права, а про активацию услуги.
- Сайт и API живут на разных доменах: нужен CORS, а сервис-воркер не должен кэшировать `/api/` — только NetworkOnly.
- D1 — это SQLite. Блобы туда не класть, фотографии только в R2.
- Телефон по `http://192.168.x.x` не даёт камеру, сервис-воркер и WebGPU — проверять только на опубликованном сайте.
- Сервис-воркер в dev выключен. Офлайн проверяется так: `npm run build && npm run preview`, открыть :4173, потом погасить сервер и перезагрузить.
- Проверять поток удобно синтетическим фото: рисуешь крышку из `uploads` на шумном фоне в canvas, кладёшь `File` в `input[capture]` через `DataTransfer` и диспатчишь `change`. Скриншот сразу после перехода в SPA часто отстаёт на кадр — состояние сверяй через JS и IndexedDB.
- Если панель браузера скрыта, `Image.decode()` в ней не резолвится и скрипт виснет — синтетическое фото собирай через `fetch` → `createImageBitmap` → `OffscreenCanvas`.
- `npm run strings` пересобирает `en.json` из таблицы дизайна; `ru.json` и `uk.json` ведутся руками.
